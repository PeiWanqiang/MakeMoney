# 策略语义锁定下的参数优化实验室

状态：Stage 1、Stage 2 已实现；Stage 3 规划中
最后更新：2026-07-31

## 1. 通用能力定义

平台从任意受支持的机器策略契约中发现可调数字槽位。在不改变交易周期、开平仓动作、多空方向、指标与行情字段、比较符、布尔结构和成交时序的前提下，系统构造有限个参数候选，并使用同一份不可变历史数据执行可审计实验。

该能力不以某个策略、标的、周期、语言或数字常量为边界。无法通过机器契约和确定性执行器表达的参数，不会因为模型提示词或某个样例需要而被标记为可优化。

## 2. Stage 1：语义锁定搜索

### 参数契约

- 条件表达式数字参数：指标周期、比较阈值和受限算术常量。
- 决策参数：仓位数值、止损比例和止盈风险回报比。
- 指标 lag/offset 默认锁定，避免无意改变时间引用和未来数据边界。
- 每个参数具有稳定 ID、原始值、数值类型、单位、建议范围和硬安全边界。
- 一次最多选择 4 个参数，每个参数 2～7 个取值点，单轮最多 16 个候选。

服务端根据原始契约生成结构骨架，将允许变化的数字槽位替换为占位符并计算 SHA-256 指纹。浏览器不能提交修改后的契约，只能提交服务端签发的参数 ID 和范围。每个候选都由服务端从原始契约生成、重新校验，并再次比较结构指纹。

候选按确定性网格生成，组合数超出预算时按固定位置采样。当前支持稳健综合、收益优先和回撤优先三种确定性评分；低交易样本、训练/验证差异和验证回撤会产生惩罚。如果候选没有超过通用改进门槛，系统保留原始参数，不强行推荐变化版本。

## 3. Stage 2：稳健性门禁

### 时间与信息隔离

- 总历史前 80% 是开发区间，最后 20% 在实验创建时封存为最终盲测。
- 开发区间约前 70% 用于训练、后 30% 用于时间顺序验证，对应总历史约 56% / 24% / 20%。
- 指标可以读取绩效窗口之前的历史做 warm-up，但预热区间不允许交易、挂单或计入收益曲线。
- 开发区间再执行 3 个 anchored walk-forward 窗口，候选至少在 2 个窗口守住相对收益、回撤和最低交易样本门槛。

### 稳健性证据

- 参数邻域：对每个选中参数做相邻一步的上、下扰动，至少 60% 的有效邻域点不能显著坍塌。
- 成本压力：使用当前成本、双倍成本和严重冲击三组费用/滑点情景。
- 市场状态：按滚动收益和波动率的相对分位数披露上涨、下跌、震荡和高波动状态下的成交、胜率和净盈亏；这是证据分层，不是单独放行门槛。
- 多次选择：披露候选数量和一个明确标注的选择惩罚后 Sharpe 启发式值。它不是 Deflated Sharpe Ratio，也不冒充统计显著性检验。

只有“相对原始参数有改进、walk-forward 通过、邻域稳定、成本压力通过”同时成立，最终盲测按钮才会开放。

### 一次性最终盲测

- 每个实验的盲测状态持久化为 `reserved → running → passed/failed`，原子领取避免并发请求重复消费。
- 会话、策略版本、参数范围、数据摘要和回测配置共同生成确定性实验 ID；完全相同的实验只恢复原记录，不能换一个 ID 重看同一盲测。
- 揭示前重新读取同一历史范围并校验 K 线摘要；快照变化时停止，不混用新数据。
- 候选参数在揭示前已经固定。盲测只放行或否决，不参与重新选参。
- 首次完成后保存不可变收据；重复请求只返回同一收据，不再次执行。
- 最低门槛为至少 2 笔盲测交易，且相对原始策略的收益和回撤不能超过既定退化容忍度。

盲测通过后，用户可以创建一个新的不可变策略记录。该版本保留父策略、实验 ID、语义锁、参数差异和生成来源。Web 当前以机器契约作为确定性执行真相，因此参数版标记为 `contract-derived`，不会伪造一份尚未物化的 TypeScript 源码。

## 4. 性能与缓存

- 单次实验只加载一次 K 线，不为每个候选请求行情。
- 历史数据读取顺序为本地静态库、进程热缓存、R2 持久缓存、官方归档冷启动和 REST 最后兜底。
- 实验缓存键包含契约、语义锁、参数范围、目标、预算、回测配置、K 线摘要和引擎版本。
- 完整实验收据和盲测状态写入 D1，重复计算结果写入 R2，并用进程内热缓存消除同实例重复执行。
- 同步 Worker 仍只适合有界小实验；更大搜索空间和多人同时运行需要异步任务队列、并发配额、取消、重试和进度持久化。

## 5. 当前真实边界与下一阶段

- Stage 2 的门槛是工程化稳健性过滤，不构成未来收益保证或正式统计显著性证明。
- 市场状态使用样本内相对分位数；尚未使用外部宏观标签或跨市场验证。
- 当前是 bar 级成本压力，没有订单簿冲击、排队、延迟分布或容量模型。
- 新参数版本的程序源码物化尚未实现；Web 回测读取其服务端契约执行，源码字段保持空白并明确标记来源。
- 登录、对象所有权、付费配额和异步长任务仍未完成。

Stage 3 是“AI 实验研究员”。AI 只能解释参数、建议有界范围、提出下一轮实验和说明脆弱性；不能改写指标、扩大安全边界、读取最终盲测后继续拟合，或把结构变化伪装成参数优化。指标、规则或动作变化必须创建显式策略分支并由用户确认。

## 6. 泛化验收证据

- 原始回归：算术回撤比例和账户权益仓位继续由完整回测执行。
- 参数变体：比较阈值与止损比例可以同时进入有界实验。
- 结构变体：RSI 周期和阈值能被发现，lag=0 保持锁定。
- 边界拒绝：未知参数 ID 在执行前返回 400；预门禁失败时盲测保持封存且不读取数据。
- 一次性状态：相同输入只映射到一个实验；盲测第二次请求只复用收据；版本创建第二次请求只复用同一策略 ID。
- 语义一致性：每个候选和新版本均重新通过契约校验与结构指纹比较。
- 既有回归：Web 构建、服务端渲染和全部自动测试继续通过。
