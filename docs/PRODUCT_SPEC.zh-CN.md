# 产品规格：Crypto Strategy Studio

状态：Draft v0.1  
目标市场：国际加密货币交易者  
首发语言：英语  
首发交易场所：Hyperliquid  
首发标的：BTC、ETH、SOL 永续合约

## 1. 产品定义

### 1.1 一句话定位

Turn any crypto trading idea into a strategy you can verify, simulate, and run.

将用户用自然语言描述的交易想法，转换为确定性的策略，完成可信回测、实时模拟和受控实盘。

### 1.2 不是什么

- 不是 AI 喊单群。
- 不是保证收益的自动交易机器人。
- 不是让大模型根据新闻自由决定每笔交易。
- 不是第一天就覆盖所有交易所和金融品种的量化平台。
- 不是托管用户资金的钱包或交易所。

### 1.3 核心价值

交易者通常面临四个断点：有想法但不会编码；能回测但结果不可信；策略上线困难；上线后缺少风险控制和复盘。平台把这四段连接为一条可审计路径。

### 1.4 产品承诺

- 从想法到首个有效回测，目标时间小于 5 分钟。
- 每一个回测结果都展示成本、假设、数据范围和局限。
- 同一策略在回测、模拟和实盘中保持一致语义。
- 用户能解释策略为何产生每一次订单意图。
- AI 服务失效时，正在运行的策略不会改变逻辑或失去风控。

## 2. 目标用户

### 2.1 首要用户：有经验的主观交易者

特征：

- 已经在交易 BTC、ETH 或 SOL 永续合约。
- 能描述自己的入场、出场和风险规则。
- 不熟悉 Python、Pine Script 或完整量化工作流。
- 愿意为节省研究和监控时间付费。

核心任务：把个人经验变成可验证、可重复运行的策略。

### 2.2 次要用户：交易内容创作者

特征：

- 在 X、YouTube、Discord 或 Telegram 发布交易观点。
- 希望用透明记录建立可信度。
- 希望发布、迭代和商业化自己的策略。

核心任务：把观点变成有版本、有记录、可被关注的策略资产。

### 2.3 后续用户：半专业量化交易者

特征：

- 已会写代码，但希望快速生成策略原型。
- 需要更可靠的数据、运行托管和跨交易场所能力。

核心任务：缩短研究到部署的周期。

### 2.4 暂不主动服务

- 完全不了解杠杆和爆仓的新手。
- 只寻找“今天买什么”的信号用户。
- 高频做市、套利和毫秒级执行团队。
- 需要机构级组合、合规报表和多人审批的基金客户。

## 3. 核心产品循环

产品能力扩展遵循[泛化优先准入规范](GENERALIZATION_POLICY.zh-CN.md)：用户样例用于发现通用语义缺口和建立回归证据，不作为特殊实现分支。只有意图、契约、执行和用户解释一致，并通过变体与边界测试，产品才能展示“已支持”。

```text
描述想法
  -> AI 澄清不可量化部分
  -> 生成策略
  -> 回测并发现问题
  -> 修改或 Fork
  -> 部署模拟盘
  -> 获得真实运行证据
  -> 分享、订阅或受控实盘
  -> 根据偏差继续改进
```

平台的增长循环不是鼓励频繁下单，而是鼓励创建、验证、分享和复用高质量策略。

## 4. 策略生命周期

```text
Draft
  -> Validated
  -> Backtested
  -> Paper Running
  -> Live Eligible
  -> Live Running
  -> Paused
  -> Archived
```

关键门禁：

- `Validated`：DSL 结构、指标依赖、时间周期和风险字段均有效。
- `Backtested`：至少完成一次包含费用和资金费的回测。
- `Paper Running`：已绑定实时市场数据，使用虚拟资金运行。
- `Live Eligible`：通过产品设定的基础风险检查，用户完成风险确认。
- `Live Running`：钱包授权有效，执行服务和紧急停止机制健康。

### 5.5 回测

MVP 必须具备：

- 明确的数据起止时间和时区。
- Bar close 与 next bar 执行语义，防止未来数据泄漏。
- Maker/Taker 手续费。
- Funding 支付和收入。
- 可配置滑点模型。
- 杠杆、逐仓/全仓简化模型。
- 止盈、止损和爆仓模拟。
- Long/Short 独立统计。
- 完整订单、成交和资金曲线。
- 样本内/样本外划分。
- 相同参数下结果可复现。

P1 增加：

- Walk-forward validation。
- 参数敏感性热图。
- Monte Carlo 交易顺序重采样。
- 牛市、熊市、横盘和高波动分段。
- 真实订单簿驱动的滑点估计。
- Paper 与 backtest 偏差分析。

核心指标：

- Net return、CAGR。
- Maximum drawdown、drawdown duration。
- Sharpe、Sortino、Calmar。
- Profit factor、expectancy、win rate。
- Exposure、turnover、trade count。
- Fees、funding、slippage 分项。
- Long/Short 和不同市场阶段表现。

### 5.6 AI 结果解读

- 用普通语言总结策略如何赚钱和亏钱。
- 指出样本太少、过拟合、单次交易贡献过高等风险。
- 找出最差的市场阶段和连续亏损区间。
- 比较两个策略版本的实质变化。
- 建议实验方向，但不将建议直接部署至实盘。
- 所有结论链接到对应数据和交易记录。

### 5.7 实时模拟盘

- 使用与实盘相同的实时行情和策略运行时。
- 独立虚拟账户、余额、仓位和盈亏。
- 模拟费用、资金费和滑点。
- 断线恢复后补放缺失事件。
- 策略状态、最后心跳和下一次评估时间可见。
- 支持暂停、恢复和停止。
- Paper 运行记录不可被用户选择性删除；可归档但保留历史。

### 5.8 受控实盘

实盘属于 P1，不作为首个公开 MVP 的上线前置条件。

- Hyperliquid API Wallet/Agent Wallet 授权。
- 用户设置最大名义仓位、杠杆和允许交易的品种。
- 下单前经过独立风险引擎。
- 订单意图、交易所订单和成交三层记录。
- 使用客户端订单 ID 保证幂等。
- 自动重连、状态对账和异常暂停。
- Dead Man's Switch 和一键撤销授权。
- 不支持转账和提现权限。

### 5.9 风险中心

MVP：

- 单笔最大风险。
- 最大仓位与最大杠杆。
- 每日亏损上限。
- 最大策略回撤。
- 最大同时持仓数。
- 只减仓模式。
- 异常数据和行情断流时禁止开仓。

P1：

- 组合级敞口限制。
- 相关性约束。
- 波动率动态降杠杆。
- 多策略资金分配。
- 交易所状态和异常价差保护。

### 5.10 监控与通知

- 策略开始、暂停、失败。
- 信号产生但被风控拒绝。
- 下单、部分成交、成交和撤单。
- 止损、回撤和每日亏损触发。
- 数据流延迟或缺口。
- 钱包授权即将失效。
- MVP 支持站内和邮件；P1 支持 Telegram、Discord 和 Webhook。

### 5.11 策略资产与社区

MVP：

- 私有策略库。
- 策略版本和标签。
- 可分享的只读回测页面。
- 分享页面明确区分 Backtest、Paper 和 Live。

P1：

- 公开策略主页。
- Fork 和派生关系。
- 可验证 Paper/Live 记录。
- 创作者主页、关注和更新通知。
- 按收益、回撤、稳定性、运行时长分别排序。

P2：

- 付费策略订阅。
- 策略市场。
- 收益分成或交易费分成。
- 社区挑战赛。

排行榜不得只按绝对收益排序，避免奖励极端杠杆和幸存者偏差。

### 5.12 计费

建议测试方案：

| 套餐 | 建议价格 | 能力 |
|---|---:|---|
| Free | $0 | 有限回测、模板、公开分享 |
| Pro | $29/月 | 更多回测、完整指标、实时模拟盘 |
| Advanced | $99/月 | 多个运行策略、高级验证、通知 |
| Creator | $199/月或分成 | 公开主页、订阅、受众分析 |

P1 实盘可以叠加用户明确授权的 Builder Fee。收费必须在授权和每笔成交记录中透明展示。

### 5.13 运营与后台

- 用户、地区、套餐和额度管理。
- 模型调用、数据调用和回测成本统计。
- 策略和分享内容举报。
- 风险事件和交易异常查询。
- 数据质量仪表盘。
- 全局暂停某交易场所、品种或实盘服务。
- 用户数据导出与删除流程。
- 审计日志查询，禁止后台静默修改交易记录。

### 6.1 MVP 必须交付

2. 英文自然语言生成受约束策略程序。
3. 规则树编辑和版本管理。
4. BTC、ETH、SOL 的 15m、1h、4h 数据。
5. OHLCV、Funding、Open Interest。
6. 包含费用、资金费和滑点的确定性回测。
7. 样本内/样本外报告。
8. 实时模拟盘。
9. 基础风险限制。
10. 站内与邮件通知。
11. 可分享的回测/Paper 页面。
12. 管理后台和全局 Kill Switch。

### 6.2 MVP 明确不做

- 用户资金托管。
- 跟单和代客理财。
- 自动参数寻优后直接实盘。
- 移动原生 App。
- 多交易所实盘。
- 高频、套利、做市。
- 期权、现货组合和跨链 DeFi。
- 新闻或社交内容直接触发订单。
- 策略付费市场。

## 7. 产品门禁与安全默认值

- 新策略默认私有、默认模拟盘、默认无杠杆放大。
- 每次从 Paper 切换到 Live 都需要显式确认策略版本和风险限额。
- 修改 Live 策略会创建新版本，不热替换正在运行的逻辑。
- AI 生成的新版本必须重新回测，不能自动继承实盘资格。
- 数据缺失、价格异常、状态无法对账时只允许减仓。
- 系统无法确认仓位时必须暂停新开仓并通知用户。
- 任何收益展示同时显示时间范围、最大回撤、交易次数和运行类型。

## 8. 核心指标

### 8.1 北极星指标

每周产生有效决策证据的活跃策略数。

“有效决策证据”指完成回测、实时模拟或受控实盘中的至少一种，并且数据和运行记录完整。

### 8.2 激活指标

- 注册到首个有效策略的转化率。
- 首次输入到有效回测的中位时间。
- 首个回测完成率。
- 首周部署模拟盘的用户比例。

### 8.3 留存与商业指标

- 第2周和第4周仍有运行策略的用户比例。
- 每个活跃用户的策略版本数。
- Paper 连续运行 7/30 天的策略数。
- Free 到 Pro 转化率。
- 每个付费用户的毛利和数据成本。

### 8.4 信任与安全指标

- Backtest 与 Paper 的信号一致率。
- Paper 与 Live 的成交偏差。
- 数据缺口率和恢复时间。
- 被风控拒绝的订单意图比例。
- 未经用户预期的订单数量，目标为零。
- 交易事故、资金安全事故和重大错误展示，目标为零。

不要把用户交易次数或总杠杆作为核心增长指标。

## 9. 上线阶段

### Phase 0：研究原型

- Strategy SDK、程序编译器和沙箱。
- 历史数据采集。
- 单策略回测。
- 内部黄金用例和一致性测试。

退出条件：20个预设策略能够稳定编译和复现结果。

### Phase 1：封闭 MVP

- Web 产品。
- 对话生成、编辑、回测、模拟盘。
- 30～50名设计合作用户。
- 分享页和基础计费。
- 只销售研究、回测和模拟盘订阅，不收取交易费。

退出条件：用户无需人工帮助完成策略创建到模拟盘，且数据、回测和运行无严重一致性问题。

### Phase 2：受控实盘

- Hyperliquid API Wallet。
- 独立风控和执行服务。
- 小范围、限品种、限杠杆邀请测试。
- Builder Fee。
- 按法律顾问批准的国家 allowlist 开放，不采用“全球上线、事后排除”。

退出条件：连续运行、断线恢复、仓位对账、Kill Switch 和安全审计通过。

### Phase 3：策略网络

- 公开验证记录。
- Fork、关注、创作者主页。
- 策略订阅和收入分成。

## 10. 待验证的产品假设

1. 用户愿意用自然语言描述足够明确的交易规则。
2. “可信回测”比“AI预测”更能建立长期付费。
3. 目标用户愿意先运行模拟盘，而不是立即实盘。
4. 可验证策略页面能够在 X、Discord、Telegram 带来自然传播。
5. 用户愿意为持续运行、通知和高级验证付费。
6. Builder Fee 不会显著降低实盘转化。
7. Hyperliquid 能提供足够稳定的数据和执行接口作为首发场所。

## 11. 需要通过访谈回答的问题

- 用户现在如何把交易想法变成规则？
- 最不信任现有回测工具的哪个部分？
- 用户愿意等待多长时间才把模拟策略切到实盘？
- 用户更愿意支付订阅费、执行费还是利润分成？
- 用户会公开哪些指标，哪些必须保持私有？
- 什么证据能让用户相信一条策略记录没有被篡改或挑选？
- 用户当前主要使用哪家交易所、钱包和通知工具？

## 12. 商务依赖

产品范围、地区开放、计费和创作者功能必须与[商务与市场方案](BUSINESS_PLAN.zh-CN.md)同步评审。以下功能不得仅由产品或技术团队决定上线：

- 实盘自动执行。
- Builder Fee、推荐返佣和利润分成。
- 付费策略订阅、跟单或排行榜激励。
- 面向特定国家投放广告或邀请创作者推广。
- 使用“收益”“alpha”“自动赚钱”等营销表述。
- 新增中心化交易所 API 密钥或托管性质的功能。
